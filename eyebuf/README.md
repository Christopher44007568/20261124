# eyebuf — 双眼渲染缓冲布局对比仿真

纯 Go(仅标准库)实现的 eye-buffer 布局基准,对比三种方案:

- **independent(独立缓冲)**:每眼私有双缓冲,resize 只影响本眼。
- **atlas(双眼图集)**:双眼打包进单个连续分配,任何 resize 整体重分配并迁移健康眼像素。
- **ring(环形缓冲)**:双眼共享槽位池,按需窃取最旧未呈现槽位。

## 运行

```sh
go run .      # 打印场景 x 布局的指标表与结论
go test ./... # 校验隔离性与画面不变性
```

## 测量指标

峰值内存、复制字节、过期帧、分配失败、健康眼停顿(stall)、呈现内容错误。
每帧内容由 `(eye, seq)` 确定性生成,呈现时逐 tick 校验位模式,验证
"另一眼不被失效资源拖住、画面保持不变"。

## 场景

基线 / 单眼延迟提交 / 单眼暂停 / 分辨率热更新 / 热更新+暂停组合 /
多次热更新 / 紧张显存预算(5MiB)/ 生产者突发提交,覆盖
256–1024px 与 R8/RGB8/RGBA8/RGBA16F 格式、90–150 帧。

## 结论

独立缓冲最稳:故障域完全隔离,热更新零跨眼拷贝,预算不足时仅本眼
丢帧且旧画面保持。环形缓冲省内存但突发下丢帧。图集稳态占用最低,
但 resize 牵连健康眼(整体重分配 + 像素迁移),且原地写入有撕裂风险。
