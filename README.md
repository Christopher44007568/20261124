# stereocull — 双眼视锥剔除（Go，仅标准库）

本项目用 Go 标准库实现立体渲染的视锥剔除，核心结论是：

> **双眼并集（union）视锥通过，只代表“至少一只眼可能看见”，不代表某只眼可见。**

并集视锥只能做保守快筛（拒绝两只眼都看不见的子树），每个存活候选仍须分别
对左右眼视锥做精确测试。

## 两条管线

- `ExactPerEye`（参考实现）：左右眼各自独立地对 BVH 做一次完整精确遍历，
  共遍历两次。
- `UnionScreenFast`（生产实现）：BVH 只遍历一次。
  - 树的前几层用并集视锥做一次 AABB 快筛，整块剪掉双眼都不可见的子树；
  - 更深节点分别做左右眼 AABB 测试，让某只眼在它不可见的子树中停用；
  - 叶子只对仍激活的眼做精确球体测试；叶子 AABB 完全在某眼视锥内时
    直接整体接受，跳过逐球测试。

两条管线的每眼接受集合、单眼可见集合、最终并集在所有姿态下逐 ID 一致，
由 `TestPipelinesAgreeForEveryPose` 强制断言。头部旋转（yaw/pitch/roll）或
前后/左右平移后，快筛结果与逐眼精确相交完全相同。

## 几何与坐标

- 头局部空间：头朝 `-Z`，`+Y` 朝上，`+X` 朝左；左眼在 `+IPD/2`，右眼在 `-IPD/2`。
- 视锥为 6 个内朝向半空间（near/far/left/right/top/bottom），在头局部空间
  构建后经四元数旋转 + 平移变换到世界空间。
- 平行立体下，并集视锥是双眼视锥的精确凸包：共享 near/far/top/bottom，
  左右侧平面各取一只眼的外侧平面。任何被并集拒绝的物体必然被双眼拒绝。
- 集合用位图 `IDSet`（`[]uint64`）存储，避免热路径上的 map 哈希与扩容。

## 场景覆盖

每个场景是一个确定性抖动网格加若干手工放置的边界实例，覆盖四类参数族：

- `wide-angle`：大垂直 FOV、夸大的 IPD，产生明显的双眼间隙；
- `narrow-angle`：小 FOV、加大 IPD，视锥很窄、并集误筛比例高；
- `ipd-shift`：大 IPD 偏移，单眼可见实例最多；
- `near-boundary`：很小的近裁面，贴近 near 平面与视锥侧边界。

手工实例包括：

- `left-only` / `right-only`：仅一只眼可见；
- `union-gap-ghost`：落在左右眼视锥之间的间隙里，被并集接受却被双眼拒绝
  （并集假阳性 / false positive）；
- `left-boundary-kiss` / `right-boundary-kiss`：球体贴着眼外侧平面；
- `near-plane-kiss`：球体跨越近裁面。

## 输出与运行

```bash
go test ./...            # 几何、并集包含性、两管线一致性、特殊实例断言
go test -race ./...      # 竞态检测
go test -bench . ./...   # 两条管线的基准对比
go run ./cmd/stereocull  # 生成 artifacts/culling_report.txt
```

报告对每个场景 × 每个姿态给出：

- 每只眼的候选（candidates）、接受（accepted）、拒绝（rejected）；
- 并集快筛的节点测试数、剪枝数、接受/拒绝；
- 最终并集、双眼共有、仅左眼、仅右眼、并集假阳性计数与特殊实例 ID；
- 两条管线的平均遍历纳秒与加速比。

## 耗时解读

加速比随视锥外场景占比变化：视锥外物体越多、并集在树顶剪掉的子树越大，
快筛收益越高（本基准中最高约 1.9x）；当绝大多数实例都落在视锥内时，
快筛需要维护两套结果，可能略慢于两次精确遍历。这与工程经验一致——
并集快筛的价值在于减少大范围不可见空间的遍历，而非让视锥内的逐眼判定消失。
