# Compositor occlusion comparison

这是一个仅使用 Go 标准库的合成器遮挡验证程序。它比较三种深度提交：

- 无深度：只使用显式 back-to-front 顺序。
- 稀疏深度：部分像素缺失深度，缺失处回退到显式顺序。
- 完整深度：每个覆盖像素都有量化后的深度。

场景包含近处手部、中间面板和远处系统通知。每一帧都会分别评估左眼和右眼，并记录逐像素覆盖决策与相对于未量化真值的遮挡错误。

## 运行

```bash
go run .
go run . -format json
go run . -format json -out report.json
go test ./...
```

默认输出 Markdown。`-format json` 输出完整逐像素记录，包括每个覆盖层在当前眼的深度、有效性、是否被选中、回退原因以及遮挡错误。
仓库中的 `report.md` 是由默认命令生成的三模式对照报告。

## 遮挡策略

1. 每个像素只读取当前眼别的深度数组。右眼不会回退到左眼数据。
2. 所有覆盖层都有有效深度时，选择当前眼最近的有效表面。
3. 任意覆盖层缺少深度或深度无效时，不把无效值当作 0、无穷大或其它有效深度。该像素使用显式提交顺序，并记录为 `ambiguous`。
4. 量化后两个表面的深度区间重叠时，仍保留较近提交值，并记录 `nearest-depth-quantization-ambiguity`。显式顺序只用于稳定并列选择。
5. `System` 标记仅用于报告，不参与排序。系统通知可以被手部或面板正常遮挡。

这些规则避免了两类错误：系统层默认永远在最前，以及右眼复用左眼深度。

## 内置场景

主场景为 12 x 8：

| 表面 | 覆盖 | 深度 |
|---|---|---|
| 手部 | 右侧近场 | 约 0.32 m |
| 面板 | 中央 | 约 1.2 m |
| 系统通知 | 全屏远场 | 约 7.0 m |

手部区域同时覆盖面板和通知；面板区域覆盖通知。三种提交都会在左、右眼分别逐像素比较。

Markdown 报告包含：

- 三种提交的正确像素数、错误数、回退数、无效深度样本数和量化歧义数。
- 左右眼的覆盖决策网格。大写表示确定结果，小写表示使用了歧义回退。
- 遮挡错误明细。
- 近距离量化、无效深度和左右眼隔离的专项诊断，以及对应错误策略的负向对照。

## 专项用例

- `near-ui-quantization`：手部和系统通知量化到同一深度桶。安全策略按显式顺序保持手部在前，并记录量化歧义。
- `invalid-depth`：手部深度无效时回退到显式顺序，而不是把手部当作无穷远后让面板或系统通知抢占。
- `stereo-isolation`：左眼手部在前、右眼面板在前。负向策略复用左眼深度时会在右眼记录错误。

负向策略只用于证明错误模式会被检测到，不是生产路径。

## 代码结构

- `main.go`：CLI、Markdown/JSON 输出。
- `internal/compositor/types.go`：场景、提交、逐像素决策与错误类型。
- `internal/compositor/depth.go`：无效深度、量化、覆盖与 JSON 安全场景摘要。
- `internal/compositor/resolve.go`：逐眼遮挡解析和真值对照。
- `internal/compositor/scenario.go`：三种提交及专项诊断。
- `internal/compositor/report.go`：Markdown 报告。
- `internal/compositor/compositor_test.go`：遮挡顺序、量化、无效深度、双眼隔离和 JSON 测试。
