# XR 渲染状态机：中断外推、重定位与时钟跳变

纯 Go（仅标准库）实现的四态 XR 渲染状态机，用离散仿真回答两个工程问题：

1. 追踪中断后，旧姿态靠惯性还能外推多久？
2. 重定位更换世界原点后，旧轨迹和锚点还能不能继续用？

## 运行

```
go run .
go test ./...
```

## 四态模型

| 状态 | 进入条件 | 渲染行为 |
| --- | --- | --- |
| `NORMAL` | 样本年龄 ≤ `LostTimeoutMs`（默认 80 ms） | 短时惯性填补帧间空隙 |
| `LOST` | 样本超时 | 按策略冻结 / 限时外推 / 淡出黑帧 |
| `RELOCALIZING` | 收到原点更换事件 | 保持一帧建立新原点，重投影历史数据 |
| `RECOVERY` | 新原点首样本或同原点丢失恢复 | smoothstep 平滑位姿 + 淡入 |

迁移闭环：`NORMAL → LOST → RELOCALIZING → RECOVERY → NORMAL`；
普通丢失（不换原点）走 `NORMAL → LOST → RECOVERY → NORMAL`。

## 三种策略

- `freeze`：锁定最后一帧位姿，误差随头部真实运动线性累积。
- `inertial`：用最后线/角速度积分外推，预算 `MaxInertialMs`（默认 120 ms）
  用完后退化为冻结。
- `fade`：冻结位姿并在 `FadeOutMs` 内淡出到黑帧，重定位后在 `FadeInMs` 淡入。

## 实验结论

### 旧姿态能外推多久

外推假设速度恒定，而真实轨迹带加速度，误差按 `~0.5·a·dt²` 二次增长。
本仿真（线加速度约 1.2 m/s²）下：

- 100 ms 外推位置误差约 0.5 cm，300 ms 升到约 4.5 cm；
- 3 cm 工程阈值对应的可信外推窗口约 240 ms，状态机默认只给 120 ms 预算，
  到期主动冻结，避免误差无界增长；
- 同一段 300 ms 中断里，冻结的峰值误差（约 6.5 cm）始终大于限时外推
  （预算内约 0.9 cm）。

### 换原点后旧轨迹是否可用

旧坐标不能直接使用——它们绑定旧原点。重定位事件携带刚体变换
`Delta`，满足 `p_new = Delta · p_old`。状态机在 `RELOCALIZING` 帧把冻结位姿、
速度、整条渲染轨迹和所有锚点统一重投影到新原点：

- 重投影轨迹与新原点轨迹的最大偏差为 0（浮点精度内）；
- 锚点重投影后相对其真实世界位置的误差为 0，虚拟物体不会漂移；
- `RECOVERY` 用 smoothstep 吸收首帧跳变（本场景原始跳变约 6 cm），避免画面瞬移。

### 时钟跳变

渲染时钟向前/向后跳变超过 `ClockJumpMs`（默认 200 ms）时，状态机只重置样本
年龄基准、丢弃不可比的时间戳历史，不触发 `LOST`、不产生黑帧，渲染保持
`NORMAL`。若把时钟跳变误当成样本老化，会得到虚假的丢失超时。

## 代码结构

- `xr/math.go`：向量、四元数、刚体变换、惯性外推、slerp。
- `xr/clock.go`：可注入跳变的虚拟时钟与样本/事件/锚点类型。
- `xr/tracker.go`：解析真值轨迹、中断注入、跨房间重定位、锚点重投影。
- `xr/statemachine.go`：四态状态机与三种策略。
- `xr/scenarios.go`、`xr/scenario_clock.go`：300 ms 中断、跨房间重定位、时钟跳变。
